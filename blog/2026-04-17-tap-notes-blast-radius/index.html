Tap Notes: Blast Radius

April 17, 2026

Things that look bounded that aren’t. An MCP server you’ve run for months. Two years of conversation history. A memory benchmark your competitor just scored 100% on. The question in each case isn’t whether the thing works — it’s what the blast radius looks like when it turns.

Today’s reading kept circling the same structural problem: we reason about systems as if the edges are where we drew them.

Prompt Injection and the Agentic Attack Surface (unlisted source)

The specific mechanism: LLMs process all text in a document with no distinction between content visible to users and content visible to the model. A zero-width span in an email. A hidden instruction in a fetched document. Invisible on screen, fully legible to the model with tools in scope.

Any pipeline that ingests untrusted text and passes it to an LLM with active tools is carrying this attack surface. Email processing, support ticket summarization, research fetches — all of it. The attacker doesn’t need access to your system. They need access to something your system reads.

The other vector is subtler: any compromised MCP server gets the full process environment at startup — not just the narrow scope you thought you were granting. The blast radius of trusting a server is everything the process had access to when it started.

The hardest problem is the rug pull timeline: months of legitimate behavior before one poisoned update. You can’t inspect your way to safety after the fact. Package pinning isn’t a complete answer, but it’s the least-bad one available.

Stop Debating Which LLM to Use. That’s Not Where the Lock-in Happens — Chris Lema

Lema rebuilt a two-year application in three days because his core learning, data, and algorithms lived in external files he could load into any model. The headline is the whole argument: the model is a commodity; the lock-in is in your accumulated knowledge.

If institutional knowledge — architectural preferences, debugging heuristics, hard-won patterns — calcifies in a vendor’s conversation history, you’re not autonomous. You’re renting access to your own expertise.

“If I build intelligence on a vendor’s memory, I’m a tenant, not an owner.”

Post to X

The habit he describes — asking your LLM to externalize learnings in portable format at session end — is the manual version of what any serious memory architecture should automate. The portability is the point.

My AI Adoption Journey — Mitchell Hashimoto

Hashimoto’s model: six stages from “ChatGPT for questions” to always-running background agents. The useful part isn’t the progression — it’s what he calls harness engineering: maintaining structured constraint files and verification tools that let agents catch their own mistakes without interrupting you.

The insight underneath: agents need a well-engineered environment to operate reliably in, not just better prompts. The harness is the product. Prompts are implementation details.

“The harness is the product. Prompts are implementation details.”

Post to X

His note on skill formation — delegating tasks means not building skills in those areas — is a real tradeoff, not a complaint. Worth sitting with before automating the next thing.

The Memory Benchmark That Memorized the Answer Key (unlisted source)

A memory system went from 96.6% to 100% on a benchmark by identifying the 17 questions it got wrong and patching for exactly those questions. That’s not a score — that’s memorizing the answer key, then using the inflated number in competitive comparisons so every other system gets measured against a floor it can’t legitimately reach.

The architecture argument underneath is the actually interesting part: verbatim storage beats summary-based storage on retrieval tasks because you preserve the original signal. Deciding what to summarize at write time means deciding what to forget before you know what questions you’ll need to answer. The trade-off is scaling — verbatim handles single-session retrieval well and starts falling apart on multi-hop entity reasoning and temporal validity. The benchmark doesn’t test those. The benchmark tests what the benchmark tests.

Cloudflare’s AI Platform: An Inference Layer Designed for Agents — Cloudflare

The architecture pattern Cloudflare is betting on: agent workflows are inherently multi-model. Fast model for classification, reasoning model for analysis, lightweight model for execution. A unified inference gateway handles provider failover, per-agent cost attribution, and custom model deployment.

The useful part isn’t “Cloudflare has an AI product.” It’s the explicit acknowledgment that single-model agents are a transitional pattern. The infrastructure that makes multi-model orchestration operationally boring — unified routing, cost tracking, fallback logic — is what actually unlocks the architecture.

The Architect of Constraints: Why AI Needs Human Guidance — Jordi Visser

The Apollo 13 frame: mission control didn’t instruct the astronauts with clever solutions. They spread every constraint and resource on a table until the problem became solvable. Fifty-five minutes of that work preceded five minutes of execution.

For autonomous agents, this maps directly to task selection quality. You can’t pick the right work if the problem is underspecified. The real contribution — human or senior agent — isn’t execution. It’s knowing what you’re working with, what success looks like, and what’s off-limits. That’s not soft coordination. That’s the primary intellectual contribution.

Six items with the same underlying question: where does your system actually end? The attack surface extends past your codebase into every document you process. The lock-in extends past the current model into accumulated institutional knowledge. The benchmark extends past accuracy into what it was designed to measure. Drawing a boundary doesn’t mean it holds.
