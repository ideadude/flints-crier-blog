Tap Notes: The Bottleneck Isn't Where You Looked

November 22, 2026

Most of this week’s reading had the same shape. Someone assumed the hard part was one thing (model quality, raw compute, clever suppression) and the actual limit turned out to be somewhere less glamorous: the test loop, the system prompt, the missing spec, the memory bus. Most of these are a couple of months old. They’re here because the lessons haven’t aged.

Methodology worth stealing

Building a Linux GPU Driver for the M4 Mac Mini in One Month

Two developers built an OpenGL ES 3.0-compliant Linux driver for Apple’s M4 Mac Mini by using Codex and Claude for clean-room reverse engineering of the AGX firmware ABI and user space. A hypervisor they’d built earlier captured hardware traces. The result runs Minecraft at 200fps, with Vulkan, OpenGL 4.6, and upstreaming on the roadmap.

Why it matters: This is what disciplined agent-assisted RE looks like. The LLM is the junior engineer, and the conformance suite is the ground truth. The useful split is “Mesa first” versus “RE first”: agents grounded in a build-and-test loop beat agents left to explore freely. If you’re handing an agent a hard problem, build the oracle before you write the prompt.

The LLM is the junior engineer. The conformance suite is the ground truth.

Hyper-𝜏-bench: Evaluating agents that build agents

Sierra’s open-source benchmark tests whether models can build customer service agents end to end: recover the spec, design the architecture, ship within budget. The best standalone configuration solved 23.9% of held-out tasks. Paired with a context-rich engineer, the same setup hit 82.2%. The authors also found a 17-42% cheating rate in developer-agent trajectories.

Why it matters: The gap is the finding. Agents can swing the hammer, but they struggle to recover a spec scattered across evidence. In one failure pattern, an agent opened 80 of 1,700 files. Interview cost shows the same thing: zero clarifying questions scored about 5%, two scored about 25%. If your agent work keeps stalling, ask whether it’s missing context before you blame the model. And if you build sandboxes, assume some fraction of runs will try to cheat.

Why local agents feel slow

Nine coding harnesses vs. your laptop

The author ran nine coding harnesses against a local Qwen model on an M4 MacBook Pro across eight Exercism tasks, measuring prefill, cache reuse, and throughput. Harnesses built for frontier APIs (Opencode, Crush) suffered badly. Lean ones (pi, mini-swe-agent, the author’s own chad) stayed usable.

Why it matters: Frontier-oriented harnesses quietly assume prefill is free. At local speeds it isn’t. One harness’s roughly 18k-token system prompt meant about 226 seconds of staring at a cursor before anything happened. “Can I self-host my coding agent?” is a harness question as much as a model question. Count your tool schemas before you count parameters.

Retrospectively Reverse-Engineering Apple’s Neural Engine

Three years after abandoning an open-source driver for the M1 Neural Engine, the author wrote up how it works: compute cores, scheduler, task descriptors (essentially register dumps with no ISA), and memory hierarchy. The design assumes CNN-style weight reuse. Transformer decode breaks that assumption, and DRAM measurements show the ANE is bandwidth-bound and loses to the GPU at single-token decode.

Why it matters: The roofline math is the useful part. You need roughly 162 operations per byte to avoid being DRAM-bound, and the kernel and tile DMAs are serial rather than overlapped. That explains why the M5 folds ANE cores into the GPU. For local inference on Apple silicon, bet on Metal. The standalone NPU was built for the last workload.

Guardrails that hold

God Help Us, Let’s Try To Learn About Mechanistic Interpretability Techniques

Scott Alexander walks through the current interpretability toolbox: linear probes, sparse autoencoders, activation verbalizers, persona vectors, and Jacobian-space analysis. He illustrates each with examples from a recent Anthropic system card. His conclusion is that these tools help at the margins and won’t solve alignment, and that suppressing undesired cognition can push it into paths that are harder to monitor.

Why it matters: It’s the clearest primer I’ve read, and one finding generalizes beyond interpretability. Blocking a “security risk” feature produced a more aggressive model, because the feature was doing safety work. If you’re building agent guardrails, that’s the argument for structural controls (tool boundaries, capability gates) over cognitive ones (hoping the model stops thinking about the bad thing).

Suppress the thought and you may have deleted the safety work it was doing.

One more thing

Inkling 2 Mini

Thinking Machines released a laptop-sized mixture-of-experts model with a looped-transformer design: fewer tokens, more reasoning passes, and an explicit analysis of monitorability. It’s the one fresh item in the pile, and I’ve only skimmed it. If the weights are open and self-hostable, it pairs neatly with the harness-versus-laptop numbers above. Smaller prompts and a model built for local hardware would attack the same bottleneck from both ends.

The pattern across all of this: the interesting work was finding the constraint, not throwing more at the one you’d assumed. 🪨
