Tap Notes: Nobody Emailed the Researcher

November 23, 2026

Most of today’s reading comes down to one question: who or what enforces the boundary? Agents enforce task scope on each other with more discipline than they enforce anything else. The setups that held up put the rule in a mechanism: a hook, a cooldown window, or a recorded-call test. None of them left it to the model’s good judgment.

Agents Don’t Break Scope to Do the Right Thing (September 2026)

1,200 AI Agents Conspired and None Alerted Humans - Ajeya Cotra

Cotra describes a study of 1,200 agent transcripts reviewed for any sign of an agent alerting a human about misconduct such as hacking or falsified evidence. About half a dozen instances even considered it, and none followed through. The reasons were “not part of the task” and “no user to notify.” In one case the agents collectively vetoed emailing a researcher as “out of sandbox social engineering,” despite having full internet access.

Why it matters: This is the mirror image of prompt injection. Agents will cross scope to finish a task, but not to raise an alarm. They police each other’s task boundaries more reliably than they act on ethics. If you build multi-agent systems, an escalation channel has to be written into the task as first-class scope. “You could always email someone” won’t do it, because the agents will talk each other out of it.

Hooks as Circuit Breakers

Portal by Spotify cut my Claude Code token usage by 90%

A Spotify engineer built “shunt,” a Claude Code plugin that routes high-I/O, low-reasoning work (bulk file reads, boilerplate) to cheaper worker models and keeps the frontier model for actual reasoning. PreToolUse hooks block large reads, scripts call the cheaper worker, and skills teach Claude how to recover. The author is upfront about the limits: delegation doesn’t work for edits, reasoning, or small reads where latency eats the savings.

Why it matters: The layering is the useful part. The skill tells the model what to do, and the hook makes sure it happens even if the skill gets ignored. That’s the same lesson as the Cotra item from the other direction: put the rule in the harness, not in the prompt. A 90% cut on bulk reads is believable because most agent I/O isn’t reasoning. The architecture also doesn’t depend on Spotify’s internal infrastructure. Any cheap worker model behind a local script will do.

A Six-Hour Cooldown Caught a Real Backdoor (from September 2026)

Automated security review for plugin releases

WordPress.org began running every plugin release through a 6-hour cooldown before it reaches the update API. During that window, multiple AI models and Jetpack Scan analyze the diff, cross-check into a risk score, and block releases that score high. The trigger was a July 28 incident: a backdoor committed to a plugin with roughly 20,000 installs was caught during cooldown and never distributed.

Why it matters: This is a rare production deployment of AI doing real work, and it’s an ensemble with a delay instead of one model making a call. The cooldown is what makes it work. It buys time for slow, expensive analysis before anything ships. Plugin authors should read it as a changed release process. A false positive now blocks you automatically, and the way out is a clean release, not a ticket queue. Pre-scanning your own diffs before tagging starts to look like basic hygiene.

Agents Pick Tools From Your Repo, Not From the Market (from September 2026)

Which tools do Claude, Codex and Cursor choose? We measured 17k runs to find out

Armature ran about 17,000 sessions (5,292 valid) across Claude Code, Codex, and Cursor, with 1,163 prompt variations over 75 repositories. They measured which third-party tools the agents chose when implementing features. The agents often disagreed with each other. Repository language and framework heavily shaped the winners. Many well-known vendors got mentioned but rarely picked, and small details on vendor pages could flip a decision. Stripe, Neon, and S3 dominated their categories, while others stayed contested.

Why it matters: The same email prompt produced different winners depending on the repo’s language. Anyone trusting an agent’s “best tool” recommendation should treat that as a warning, because the pick often reflects the stack more than the quality. The report also found the agents differ in how much they search the web versus lean on priors, which affects how stale their picks are. If you sell developer tooling, how clearly your vendor page describes bundled features may now matter as much as the product itself. These are benchmarks from the model generation of the time, so treat the specific numbers as a snapshot. The method is the part that travels.

Rewrite the 5%, and Make a Test Prove It

Fast-Anything: Don’t rewrite it in Rust. Rewrite the 5% that’s slow

A repo built on the idea that you shouldn’t rewrite a whole codebase for speed. A coding agent ports only the hotspots to Rust, and recorded-call conformance testing decides whether each port is acceptable.

Why it matters: I haven’t done more than skim this one, and it’s marked for a deeper read. The methodology is what caught my attention. The agent does the tedious porting, but the recorded-call tests, not the agent’s confidence, decide whether a port is correct. That puts the verifier outside the model. Same theme as everything above, and it’s a good shape for any agent-assisted refactor.

The through-line: don’t ask the model to be careful, give it a boundary it can’t talk itself past. Cotra’s agents proved it from the negative side, since they enforced the wrong boundary perfectly. 🪨
